# Дизайн исследовательского пайплайна для криптовалют

Дата: 2026-05-11
Проект: pj22_btc

## Цель

Создать Python-проект для исследований торговых стратегий на криптовалютах, в первую очередь на BTC. Стратегии будут опираться не на технические индикаторы, а на оценку настроения рынка локальными LLM-моделями, работающими через Ollama. Проект должен поддерживать воспроизводимые скрипты, тестируемую основную логику и понятное разделение между сырыми данными, обработанными данными, LLM-оценками, кодом стратегий, результатами бэктестов и отчетами.

## Область работ

Первый каркас проекта будет исследовательским пайплайном, а не ботом для реальной торговли. На старте проект будет работать с локальными историческими OHLCV-данными и локальными входными материалами для оценки настроения рынка, например новостями, заметками, агрегированными рыночными сводками или заранее подготовленными текстовыми снапшотами. Подключение биржевых API, автоматическая загрузка данных и автоматический сбор новостей останутся следующими расширениями. Начальная структура должна позволять добавлять модели Ollama, промпты, правила интерпретации sentiment-ответов, стратегии и метрики бэктеста без смешивания экспериментальных скриптов с переиспользуемым кодом.

## Архитектура

Репозиторий будет оформлен как Python-пакет в `src/pj22_btc`. Переиспользуемая логика будет находиться в модулях пакета, а запускаемые рабочие сценарии — в папке `scripts/`. Тесты будут проверять модули пакета напрямую.

Планируемая структура:

```text
pj22_btc/
  pyproject.toml
  README.md
  configs/
    default.yaml
  data/
    raw/.gitkeep
    processed/.gitkeep
  reports/
    .gitkeep
  scripts/
    run_backtest.py
  src/
    pj22_btc/
      __init__.py
      backtest.py
      data.py
      ollama_client.py
      sentiment.py
      strategy.py
  tests/
    test_backtest.py
    test_sentiment.py
    test_strategy.py
```

## Компоненты

`data.py` будет загружать и проверять локальные данные. Для рыночных OHLCV-файлов модуль должен приводить данные к ожидаемой схеме с колонками `timestamp`, `open`, `high`, `low`, `close` и `volume`. Для текстовых источников настроения модуль должен уметь читать подготовленные записи с временной привязкой, чтобы sentiment-сигналы можно было сопоставлять с рыночными свечами.

`ollama_client.py` будет изолировать работу с локальным Ollama API: адрес сервера, имя модели, параметры генерации, отправку запроса и получение ответа. Остальной код не должен зависеть от деталей HTTP-вызова.

`sentiment.py` будет формировать промпт для LLM, вызывать клиент Ollama, разбирать ответ модели и приводить его к структурированному sentiment-сигналу. На старте сигнал можно представить как числовую оценку, например от `-1.0` до `1.0`, и текстовое объяснение модели. Ответ модели должен сохраняться или логироваться так, чтобы результат эксперимента можно было перепроверить.

`strategy.py` будет содержать правила стратегий, которые преобразуют sentiment-сигналы в торговые решения. Первая стратегия может быть специально простой: открывать или удерживать позицию при достаточно позитивном настроении, выходить или оставаться вне рынка при негативном или неопределенном сигнале.

`backtest.py` будет преобразовывать рыночные данные и сигналы стратегии в сделки, кривую капитала и сводные метрики. Первая версия должна быть прозрачной и осторожной, без лишней сложности.

`scripts/run_backtest.py` будет читать конфигурацию, запускать стандартный сценарий оценки настроения и бэктеста, затем сохранять результат в `reports/`.

## Поток данных

Исторические OHLCV-файлы и подготовленные текстовые материалы для оценки настроения хранятся в `data/raw/`. Функции обработки читают сырые файлы, проверяют схему, при необходимости сохраняют очищенные данные в `data/processed/`, затем передают текстовый контекст в `sentiment.py`. Модуль sentiment вызывает локальную модель через Ollama и формирует структурированные сигналы. Стратегия преобразует эти сигналы в позиции, модуль бэктеста рассчитывает результаты, а скрипт сохраняет человекочитаемый отчет или CSV-результаты в `reports/`.

## Обработка ошибок

Функции загрузки данных должны выдавать понятные ошибки, если файл не найден, отсутствуют обязательные колонки, временные метки не удается разобрать или числовые рыночные колонки содержат некорректные значения. Контур Ollama должен явно сообщать, если локальный сервер недоступен, указанная модель не найдена, ответ модели пустой или его невозможно разобрать в ожидаемый формат. Скрипты должны показывать эти ошибки без маскировки, чтобы неудачные эксперименты было легко диагностировать.

## Тестирование

На первом этапе тесты должны проверять чистую логику: разбор sentiment-ответов, преобразование sentiment-сигналов в торговые решения и базовую бухгалтерию бэктеста. Для unit-тестов предпочтительны небольшие DataFrame-фикстуры прямо в тестах, чтобы ожидаемое поведение было видно без зависимости от больших файлов с рыночными данными. Вызовы Ollama в unit-тестах должны мокироваться; живые проверки с реальной локальной моделью можно добавить отдельно как ручной или integration-сценарий.

## Окружение

Локальное виртуальное окружение называется `.venv` и создано командой:

```powershell
C:\Python\Python31313\python.exe -m venv .venv
```

Начальный набор зависимостей должен быть небольшим: `pandas`, `numpy`, `pyyaml`, `pytest`, HTTP-клиент для локального Ollama API, например `httpx`, и, возможно, `ruff` для форматирования и линтинга.
